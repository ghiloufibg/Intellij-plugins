Daily Export Pipeline

Spring Boot + JobRunr nightly job: DB → batched HTTP enrichment (2 independent services) → gzipped CSV → multipart upload to ms-storage (the GCP access microservice).

Java 21 · Spring Boot 3 · JobRunr · no Spring Batch · prototype for adaptation · 2026-08-20

1. Design summary

JobRunr cron 0 0 * * * (Europe/Paris) — distributed lock, retries=5, no dashboard → for each missing businessDate (catch-up), then J-1: dailyExport(businessDate) // ONE DATE = ONE IDEMPOTENT RUN └ keyset pagination over [date, date+1) // constant memory, no OFFSET └ enrichment: batches of 100 → services A and B called in parallel per batch (independent) → virtual threads, Semaphore(8) + retry(3, backoff+jitter) PER service └ append to export-{date}.csv.gz.tmp // GZIPOutputStream + BufferedWriter, flush/chunk └ multipart POST to ms-storage // FileSystemResource: streams from disk └ markCompleted(date) only after HTTP 200 // ms-storage acks only after GCS close() └ finally: delete tmp file → any failure at any step: JobRunr replays the whole date (safe: idempotent by filename)
  • ResilienceCoarse-grained retry: replaying a date is the answer to every failure. GCS object atomicity + filename idempotency make replays safe.
  • EfficiencyMemory is O(chunk), never O(dataset). Gzip cuts disk/network ~5–10×. Upload is a short, full-throughput connection.
  • Simplicity~300 lines, one dependency added (JobRunr). Hand-rolled retry and CSV escaping to stay dependency-light.
  • Unbounded dataKeyset pagination + streaming append + streamed multipart. Memory stays constant regardless of volume; only local disk is consumed, and gzip keeps that small.

/*
 * ============================================================================
 *  DAILY EXPORT PIPELINE — single-file prototype
 * ============================================================================
 *  Design: JobRunr recurring job (midnight Europe/Paris)
 *          -> keyset pagination over the business-date window
 *          -> enrichment via batched HTTP calls to TWO independent services,
 *             called in parallel per batch (virtual threads, one semaphore
 *             and one retry per service)
 *          -> streaming append to a gzipped temp CSV file (constant memory)
 *          -> short multipart upload to ms-storage (the microservice centralising GCP access)
 *          -> mark date COMPLETED only after the 200 ack
 *          -> any failure: JobRunr retries the whole date (idempotent by design)
 *
 *  Required dependencies (pom.xml):
 *    org.jobrunr:jobrunr-spring-boot-3-starter   (job orchestration: lock, retry)
 *    spring-boot-starter-web                     (RestClient)
 *    spring-boot-starter-jdbc                    (JobRunr storage + your queries)
 *
 *  Required application.yml: see the application.yml file next to this one
 *  (background-job-server enabled, dashboard disabled).
 *
 * ============================================================================
 *  CHANGES NEEDED IN ms-storage (the receiving microservice) — see also
 *  the comments in uploadToMsStorage() below:
 * ============================================================================
 *  1. MULTIPART SIZE LIMITS — the defaults (1MB/10MB) will reject real files:
 *       spring.servlet.multipart.max-file-size: 2GB      (or -1 for unlimited)
 *       spring.servlet.multipart.max-request-size: 2GB
 *     Also raise the ingress/gateway body-size limit in front of it, e.g. for
 *     nginx-ingress:  nginx.ingress.kubernetes.io/proxy-body-size: "2g"
 *     and its read timeout for large transfers:
 *                     nginx.ingress.kubernetes.io/proxy-read-timeout: "600"
 *
 *  2. THE FILE IS GZIPPED (.csv.gz) — decide ONE of:
 *       a) Store as-is in GCS (recommended: cheaper, faster). Set the blob
 *          metadata contentType="text/csv" and contentEncoding="gzip" so GCS
 *          serves it transparently decompressed to HTTP clients.
 *       b) Decompress on the fly before writing to GCS:
 *          new GZIPInputStream(file.getInputStream()) -> WriteChannel.
 *
 *  3. STREAM, DON'T BUFFER — in the endpoint, never call file.getBytes().
 *     Use file.getInputStream().transferTo(Channels.newOutputStream(
 *         storage.writer(blobInfo)))   // google-cloud-storage WriteChannel
 *     (Spring multipart already spools the upload to a temp file on disk,
 *      so heap usage stays constant.)
 *
 *  4. IDEMPOTENCY — use the received filename (export-{date}.csv.gz) as the
 *     GCS object name. Re-uploading the same date must overwrite (default
 *     GCS behaviour) or be ignored — never duplicated.
 *
 *  5. ACK SEMANTICS — return 200 ONLY after the GCS WriteChannel.close()
 *     succeeds (the object is atomic: visible only on successful close).
 *     On any exception return 5xx so this job's retry kicks in.
 * ============================================================================
 */

  @Service
  public static class ExportService {

    private static final Logger log = LoggerFactory.getLogger(ExportService.class);

    private static final int CHUNK_SIZE = 1_000;        // rows fetched per DB page
    private static final int ENRICH_BATCH_SIZE = 100;   // items per enrichment HTTP call
    // One limit PER enrichment service: an incident/slowdown on one service
    // must not throttle the calls to the other one.
    private static final int MAX_CONCURRENT_HTTP_A = 8; // in-flight batches to service A
    private static final int MAX_CONCURRENT_HTTP_B = 8; // in-flight batches to service B
    private static final int ENRICH_RETRIES = 3;

    private final RestClient restClient;

    // TODO adapt: URL of ms-storage (service name in your k8s namespace)
    private static final String MS_STORAGE_UPLOAD_URL = "http://ms-storage/api/exports";

    public ExportService(RestClient restClient) {
      this.restClient = restClient;

    /**
     * Entry point of the recurring trigger. Handles catch-up: processes every
     * business date not yet COMPLETED, oldest first, each as an independent,
     * idempotent, replayable unit.
     */
    public void runDailyWithCatchUp() {
      LocalDate yesterday = LocalDate.now(ZoneId.of("Europe/Paris")).minusDays(1);
      for (LocalDate date : findMissingDates(yesterday)) {
        dailyExport(date);
      }
    }

    /**
     * ONE DATE = ONE IDEMPOTENT RUN. Any failure anywhere -> JobRunr retries
     * the whole method with backoff; replaying a date is safe end-to-end
     * (same window, same filename, ms-storage overwrites in GCS).
     */
    @Job(name = "daily-export-%0", retries = 5)
    public void dailyExport(LocalDate businessDate) {
      log.info("Starting daily export for {}", businessDate);
      Path tmp = null;
      try {
        tmp = Files.createTempFile("export-" + businessDate, ".csv.gz.tmp");

        long written = enrichAndWriteCsv(businessDate, tmp);
        log.info("Export {}: {} rows written to {}", businessDate, written, tmp);

        uploadToMsStorage(businessDate, tmp);
        markCompleted(businessDate);
        log.info("Export {} completed", businessDate);

      } catch (IOException e) {
        throw new UncheckedIOException(e); // let JobRunr retry the date
      } finally {
        deleteQuietly(tmp);
      }
    }

    // ========================================================================
    // Pipeline core: DB chunks -> enrichment batches -> gzip CSV append.
    // Constant memory: O(CHUNK_SIZE), never O(dataset).
    // ========================================================================

    private long enrichAndWriteCsv(LocalDate businessDate, Path tmp) throws IOException {
      long totalWritten = 0;
      long failedItems = 0;

      try (var out = Files.newOutputStream(tmp);
           var gzip = new GZIPOutputStream(out, 64 * 1024);
           var writer = new BufferedWriter(
               new OutputStreamWriter(gzip, StandardCharsets.UTF_8))) {

        writeCsvLine(writer, List.of("id", "name", "field_a", "field_b")); // header — TODO adapt

        // Bounded-concurrency enrichment: virtual threads make blocking HTTP
        // calls cheap. The two enrichment services are INDEPENDENT, so each
        // batch calls A and B in parallel; each service has its own semaphore
        // and its own retry (a failure on B never replays the call to A).
        try (ExecutorService vt = Executors.newVirtualThreadPerTaskExecutor()) {
          Semaphore permitsA = new Semaphore(MAX_CONCURRENT_HTTP_A);
          Semaphore permitsB = new Semaphore(MAX_CONCURRENT_HTTP_B);

          long lastSeenId = 0;
          while (true) {
            // --- 1. keyset-paginated chunk over the frozen calendar window ---
            List<SourceRow> chunk = fetchChunk(businessDate, lastSeenId, CHUNK_SIZE);
            if (chunk.isEmpty()) break;
            lastSeenId = chunk.getLast().id();

            // --- 2. fan out enrichment batches for this chunk; inside each
            //        batch, fork the two independent service calls ---
            List<Future<List<EnrichedRow>>> futures = new ArrayList<>();
            for (List<SourceRow> batch : partition(chunk, ENRICH_BATCH_SIZE)) {
              futures.add(vt.submit(() -> {
                Future<Map<Long, String>> fromA = vt.submit(() ->
                    withPermit(permitsA, () ->
                        withRetry(() -> enrichBatchFromServiceA(batch), ENRICH_RETRIES)));
                Future<Map<Long, String>> fromB = vt.submit(() ->
                    withPermit(permitsB, () ->
                        withRetry(() -> enrichBatchFromServiceB(batch), ENRICH_RETRIES)));
                return merge(batch, fromA.get(), fromB.get()); // latency = max(A, B)
              }));
            }

            // --- 3. collect (chunk-local join keeps ordering deterministic
            //        per chunk and memory bounded) and append to the CSV ---
            for (Future<List<EnrichedRow>> f : futures) {
              try {
                for (EnrichedRow row : f.get()) {
                  writeCsvLine(writer, List.of(
                      String.valueOf(row.id()), row.name(),
                      row.fieldA(), row.fieldB()));
                  totalWritten++;
                }
              } catch (Exception e) {
                // Partial-failure policy: a batch that failed after all retries
                // is EXCLUDED from the file and counted; the run survives.
                // TODO adapt if you prefer: mark rows FAILED in DB for later replay.
                failedItems += ENRICH_BATCH_SIZE;
                log.warn("Enrichment batch dropped after {} retries", ENRICH_RETRIES, e);
              }
            }
            writer.flush(); // durability point after each chunk
            log.debug("Chunk done, lastSeenId={}, written={}", lastSeenId, totalWritten);
          }
        } catch (InterruptedException e) {
          Thread.currentThread().interrupt();
          throw new IllegalStateException("Export interrupted", e);
        }
      }

      if (failedItems > 0) {
        log.warn("Export {}: {} items excluded due to enrichment failures",
            businessDate, failedItems);
      }
      return totalWritten;
    }

    // ========================================================================
    // Delivery: short, full-throughput multipart upload of the finished file.
    // ========================================================================

    private void uploadToMsStorage(LocalDate businessDate, Path file) {
      String filename = "export-" + businessDate + ".csv.gz"; // idempotency key downstream

      MultiValueMap<String, Object> body = new LinkedMultiValueMap<>();
      // FileSystemResource streams from disk — the file is never loaded in memory.
      body.add("file", new FileSystemResource(file) {
        @Override public String getFilename() { return filename; }
      });
      // Optional explicit metadata part, if ms-storage wants it:
      body.add("businessDate", businessDate.toString());

      /*
       * MS-STORAGE SIDE (reminder, see file header for the full list):
       *   @PostMapping(value="/api/exports", consumes=MULTIPART_FORM_DATA)
       *   ResponseEntity<Void> upload(@RequestPart("file") MultipartFile file,
       *                               @RequestPart("businessDate") String date) {
       *     var blob = BlobInfo.newBuilder(BUCKET, file.getOriginalFilename())
       *         .setContentType("text/csv").setContentEncoding("gzip").build();
       *     try (var ch = storage.writer(blob); var in = file.getInputStream()) {
       *       in.transferTo(Channels.newOutputStream(ch));   // stream, no getBytes()
       *     }
       *     return ResponseEntity.ok().build();  // 200 ONLY after successful close()
       *   }
       */
      restClient.post()
          .uri(MS_STORAGE_UPLOAD_URL)
          .contentType(MediaType.MULTIPART_FORM_DATA)
          .body(body)
          .retrieve()
          .toBodilessEntity(); // non-2xx -> exception -> JobRunr replays the date
    }

    // ========================================================================
    // Small utilities (kept inline to stay dependency-free; for the CSV you
    // may swap writeCsvLine for jackson-dataformat-csv or commons-csv)

    private static <T> T withPermit(Semaphore permits, Callable<T> action) throws Exception {
      permits.acquire();
      try {
        return action.call();
      } finally {
        permits.release();
      }
    }

    private static <T> T withRetry(Callable<T> action, int maxAttempts) throws Exception {
      Exception last = null;
      for (int attempt = 1; attempt <= maxAttempts; attempt++) {
        try {
          return action.call();
        } catch (Exception e) {
          last = e;
          if (attempt < maxAttempts) {
            long backoffMs = (long) (Math.pow(2, attempt) * 500
                + Math.random() * 250); // exponential + jitter
            Thread.sleep(backoffMs);    // cheap on a virtual thread
          }
        }
      }
      throw last;
    }

    private static void writeCsvLine(BufferedWriter w, List<String> fields)
        throws IOException {
      StringBuilder sb = new StringBuilder(128);
      for (int i = 0; i < fields.size(); i++) {
        if (i > 0) sb.append(',');
        sb.append(csvEscape(fields.get(i)));
      }
      w.write(sb.append('\n').toString());
    }

    private static String csvEscape(String v) {
      if (v == null) return "";
      boolean needsQuoting = v.indexOf(',') >= 0 || v.indexOf('"') >= 0
          || v.indexOf('\n') >= 0 || v.indexOf('\r') >= 0;
      return needsQuoting ? '"' + v.replace("\"", "\"\"") + '"' : v;
    }

    private static <T> List<List<T>> partition(List<T> list, int size) {
      List<List<T>> parts = new ArrayList<>();
      for (int i = 0; i < list.size(); i += size) {
        parts.add(list.subList(i, Math.min(i + size, list.size())));
      }
      return parts;
    }

    private static void deleteQuietly(Path p) {
      if (p == null) return;
      try {
        Files.deleteIfExists(p);
      } catch (IOException e) {
        LoggerFactory.getLogger(ExportService.class).warn("Could not delete {}", p, e);
      }
    }
  }

@PostMapping(value = "/api/exports", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public ResponseEntity<Void> upload(@RequestPart("file") MultipartFile file,
                                   @RequestPart("businessDate") String businessDate) throws IOException {
  BlobInfo blob = BlobInfo.newBuilder(BUCKET, file.getOriginalFilename())
      .setContentType("text/csv")
      .setContentEncoding("gzip")           // stored gzipped, served decompressed
      .build();
  try (WriteChannel ch = storage.writer(blob);
       InputStream in = file.getInputStream()) {
    in.transferTo(Channels.newOutputStream(ch));   // stream, constant heap
  }
  return ResponseEntity.ok().build();        // 200 ONLY after successful close()
}
